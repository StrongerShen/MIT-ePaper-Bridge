# 專用 App 需求與架構

## 使用者確認的流程

```text
電腦 ← BLE 建立連線與交接下載位置 → iPhone
電腦 ─ Wi-Fi／區域網路傳圖 → iPhone 預覽
                              ↓ 使用者按更新並靠近電子紙
                             NFC → 現有 Waveshare 電子紙
```

- 電子紙保留現有 NFC 硬體；不需要替電子紙加裝 BLE、ESP32 或 NFC 橋接板。
- iPhone 是 BLE 接收端、區域網路圖片下載端與 NFC 更新端；電腦透過 BLE 提供暫存下載位置，並透過區域網路提供圖片。沒有共同網路時可手動切回純 BLE。
- 預設使用相互可連線的同一區域網路（電腦可以接有線、手機接 Wi-Fi），不使用 BLE 傳 Wi-Fi 密碼，也不自動更換手機網路。
- 電腦端採 Python／Bleak，另附 Tk 視窗；使用者已選擇先用 Mac mini 傳圖。Mac 十二項測試通過，GUI 搜尋後傳送的事件迴圈錯誤已修正，BLE 交接與區域網路收圖已實機成功；Windows 未測試。
- iPhone 使用 SwiftUI、CoreBluetooth 與 CoreNFC，原生開發以便直接控制兩種通訊。
- 收圖時保持 App 在前景；收圖與 NFC 更新分開操作，無需電腦在 NFC 更新時仍維持連線。
- 現有 NFC E-Tag 成功更新，只證明硬體與該 App 的組合可用；專用 App 的 NFC 指令仍需實測驗證。

## 目前實作範圍

- 圖片校正 EXIF 方向、透明區補白、等比例縮放補白，輸出 800 × 480 灰階原稿與黑白抖色 PNG。CLI 另支援滿版裁切與直接二值化。
- 預設 BLE 只交接圖片網址、尺寸、長度與 CRC32；電腦以短期 HTTP 服務提供一張 48000 bytes 圖片，iPhone 檢查完整性後才替換預覽並保存。下載完成確認或失敗後關閉服務。
- 純 BLE 備用模式仍逐段確認、檢查順序、長度與 CRC32。
- iPhone 預覽收到的確切點陣，使用者按「更新電子紙」啟動 NFC 工作階段。
- NFC 初版實作官方範例中的舊版 7.5 吋 `0xCD` 協定。收到刷新完成回應才顯示完成；標籤類型不符、回應異常、斷線或逾時會停止，不會以 BLE 收到圖片作為電子紙刷新成功。
- 尚未實作新版 APDU NFC 協定、原生多階灰階、背景接收或自動啟動 NFC。

## 目前驗證狀態與環境資訊

- **端到端流程已全線驗證成功**：
  - 電腦端（Mac mini）：GUI 視窗與 CLI 均可將圖片轉為 800 × 480 單色點陣，通過 12 項單元測試。
  - BLE 交接與區域網路傳圖：Mac 透過 BLE 廣播下載位址，iPhone App 透過同區域網路快速下載 48,000 位元組點陣圖並通過 CRC 驗證，iPhone 上成功顯示預覽。
  - NFC 電子紙刷新：已確認板子相容 7.5 吋舊版 `0xCD` 協定。透過 1 秒主動 RF 穩定探測與 6 ms 緊湊時序，已完成初始化、400 包圖檔寫入、刷新確認與休眠收尾，實機成功更新電子紙。
- **開發與簽章環境**：
  - 專案由 Mac mini（本機）作為主要開發維護環境。
  - Xcode 27.2、XcodeGen，簽章團隊為 MobileIT Team，已啟用 NFC Tag Reading capability 並配置 `TAG` entitlement。
  - 測試機為 Shen iPhone 16e，透過 `devicectl` 支援原生安裝與除錯。
- **後續常規操作**：
  - 臨時診斷模組（`NFCTrace` 等）已全數清理，App 與電腦端程式已正式化。可在日常工作中以 Mac GUI / CLI 進行圖檔更新。

實作與啟動方式見[開發說明](development.md)，傳輸格式見[協定說明](protocol.md)。
